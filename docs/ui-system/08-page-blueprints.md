# Page Blueprints

## Professor — Schedule

- App sidebar
- 64px schedule header
- Compact daily summary
- Full-height week/day calendar
- Contextual selection composer
- Right event drawer
- No separate dashboard required for daily work

## Professor — Students

Desktop split view:

- Left: searchable student directory, 320–360px.
- Right: selected student overview.
- Header action: Schedule lesson.
- Tabs: Overview, Lessons, Notes, Feedback.

Mobile uses directory → full detail navigation.

## Professor — Insights

- Calm report header and date range.
- 3–4 meaningful metrics, not a wall of cards.
- One primary chart per section.
- Tables for exportable detail.
- Insights remain secondary to Schedule.

## Professor — Settings

- Left settings subnavigation on desktop.
- Single content column, max 880px.
- Group by Teaching, Notifications, Profile, Language & timezone, Security, Advanced.
- Save within the affected section; avoid one giant page-wide form.

## Student — Home

Priority stack:

1. Next confirmed lesson hero card.
2. Pending request card, when present.
3. Book next lesson action.
4. Recent activity.

Do not lead with vanity metrics.

## Student — Book a Lesson

- Clear heading and timezone.
- Date choice.
- Time choice.
- Request review.
- Pending success state.
- No administrative filtering language.

## Student — My Lessons

Tabs: Upcoming, Requests, History.

Cards emphasize date/time, status, next action, and cancellation boundary. Join is dominant near lesson time.

## Student — Profile

Sections: Personal information, Learning profile, Preferences, Account, optional Referral. Backend enum values never appear.

## Authentication

- Quiet centered shell, max 440px form.
- Editorial brand panel only on wide screens.
- One primary action.
- Password requirements visible before failure.
- Verification and recovery states are explicit.

## Marketing landing

Marketing can be more expressive than the app:

- editorial display type;
- warm photography or restrained illustration;
- clear professor identity;
- value proposition and how booking works;
- one primary CTA: Find a lesson time.

Do not use fabricated statistics or generic dashboard screenshots.
