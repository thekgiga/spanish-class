# Core UX Flows

## Professor creates availability

Select range in calendar → see live start/end/duration → choose `Offer this time` → optional repeat → save → available event appears.

## Student requests a lesson

Choose date → choose available time → review local time/duration/policy → `Request lesson` → time becomes reserved → pending explanation and decision deadline are shown.

## Professor approves

Requested event is visible in calendar and attention summary → open request drawer → approve or reject → calendar updates in place → student is notified.

## Professor schedules directly

Select calendar range or open student profile → choose student → schedule → confirmed lesson is created → student notification is on by default.

## Cancellation

Show the applicable policy before the action. Require context for professor cancellation. Explain the next valid action after cancellation.

## Meeting lifecycle

Before lesson: countdown and join availability. During window: prominent join action. After lesson: professor attendance/notes and student feedback/next-booking action.
