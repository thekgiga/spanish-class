# Implementation Roadmap

## Phase 0 — Audit and regression baseline

Inventory routes, components, APIs, state, permissions, localization, responsive behavior, and tests. Add critical-flow regression coverage.

## Phase 1 — Semantic design-system foundation

Consolidate tokens without creating another palette. Establish primitives, composites, domain status mapping, Storybook states, and accessibility checks.

## Phase 2 — Application shell

Migrate professor/student navigation, headers, notification access, profile menu, responsive shell, and route architecture.

## Phase 3 — Professor schedule workspace

Calendar range selection, live duration, offer/schedule/block composer, event states, event drawer, recurring availability, mobile agenda, and keyboard alternatives.

## Phase 4 — Student request and professor approval

Student date/time choice, review, pending explanation, expiry, calendar attention state, approval/rejection drawer, conflict handling, and notifications.

## Phase 5 — Lessons and students

Student Home, My Lessons, professor directory, student detail, lesson timeline, attendance, notes, feedback, and direct scheduling.

## Phase 6 — Supporting capabilities

Settings, security, analytics, email logs, referrals, authentication/onboarding, cancellation, and notification preferences.

## Phase 7 — Premium polish and legacy removal

Spacing/type/icon audits, motion, skeletons, localization QA, visual regression, responsive QA, accessibility QA, and removal of unused legacy CSS/components.

## Execution rule

Implement one vertical slice at a time. A phase advances only after its exit criteria and matrix requirements are proven.
